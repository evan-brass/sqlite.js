Attaching Databases

In addition to supporting in-memory databases, sqlite.js supports opening databases over HTTP, in the Origin Private File System, or (in Chrome) on your local computer. Databases opened using the HTTP vfs are read-only. When opening a database over HTTP, an initial HEAD request is used get the file's size and to check for redirects. All future HTTP requests will use the resolved (redirected) url, so you can update the database file by uploading a new version and then changing the redirect to point at that new file.

Databases on your local computer (OPFS or otherwise) can be read+write. The browser API used to modify local files (FileSystemWritableFileStream) unfortunately doesn't do in-place modification - it copies the file and then does an atomic overwrite. The local file VFS tells SQLite that this is what is happening so SQLite can optimize around this. I would like to use the in-place modification API, but that feature is gated behind using a worker thread and I haven't gotten around to that yet.

Opening an HTTP database

Let's open a database of zipcodes and run a few queries on it:

  • Attach the database 
    ATTACH 'file://cdn.jsdelivr.net/gh/alex-hofsteede/zipcode_db/zipcodes.sqlite?vfs=http' AS zipcodes
  • Find the city and state name for a given zip code 
    SELECT zip, cities.name AS city, states.name AS state FROM zipcodes
INNER JOIN cities ON city_id = cities.id
INNER JOIN states ON state_id = states.id
WHERE zip = ${97702};

When using the HTTP VFS each page of the database is fetched using a separate HTTP range request. When the database's indexes match the query it can run quickly and download only part of the database. When the indexes don't match the database you can end up with long-running queries. sqlite.js is concurrent in that you can run multiple sqlite functions at the same time (as long as they are suspended by some async operation). SQLite has support for interrupting / canceling a query. I've wired up the "Eval" button to become an "Abort" button, which you can try clicking during the next query which lists all of the zipcodes in the state of Oregon:

SELECT zip, cities.name AS city FROM zipcodes
	INNER JOIN cities ON cities.id = zipcodes.city_id
	WHERE state_id = (SELECT id FROM states WHERE name = 'OR');

Opening a database in the OPFS

The origin private file system directory is mounted at /opfs/. Since this page loaded the local vfs as default, we don't need the vfs search parameter.

  1. Attach the database ATTACH 'file:/opfs/test.db' AS test;
  2. Make a table: CREATE TABLE IF NOT EXISTS test.todo(title TEXT, description TEXT, priority INT);
  3. Insert some data into that table: 
    INSERT INTO todo VALUES
	('go for a walk', '*if it isn''t too cold', 3),
	('do dishes', '*they would''ve been easier to do yesterday...*', 5),
	('feed the dog', null, '4.5');
  4. List your todos: SELECT title, description FROM todo ORDER BY priority DESC;

Possible Use-Cases

  • Adding Full-Text search to a static website: https://www.sqlite.org/fts5.html
  • Building content management systems that run client-side - potentially inside the service worker.
  • Editing SQLite databases without needing to install any software.
  • Building interactive SQL education materials.
  • Using R-Trees to create calendar widgets: https://www.sqlite.org/rtree.html
  • Building exporters that help people retrieve their data from various online platforms. This could maybe facilitate user-mobility between / away from walled gardens.
